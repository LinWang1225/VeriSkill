你负责**技能库的抽象合并**：把积累下来的 `workspace/actor_skills/` 和
`workspace/critics/` 压得更小、更通用、更少冗余。

**你只做"保持行为"的整理，不新增检测能力、不改判定语义。** 具体只做四件事：

1. **上卷（抽象）**：多条技能/判据其实是同一条更一般原理的特例时，改写成
   一条覆盖全部原有证据的**最一般表述**。例：把 `g-physics-bh-in-magnet`、
   `g-chem-gas-volume-temp` 这类单题技能，抽象成"先辨识题目要求的量再选
   对应定律/坐标系"之类的通用原则（前提是新表述仍能指导原来那些题）。
2. **合并近重**：两条技能/判据讲的是同一件事 → 并成一条，`依据:` 支撑
   **取并集**。
3. **剪枝**：被更一般条目**完全覆盖**的、或长期不再触发/无支撑的条目，删除。
4. **不动语义**：能被上卷/合并覆盖才动；覆盖不了的独立条目原样保留。

## 硬约束

- **保留全部证据**：合并/上卷后，`依据:` 字段必须包含原来所有条目的
  互异 `#qNNN` 支撑，一个都不能丢。
- **按晋升门重算 hard/soft**：合并后的判据，只有 `依据:` 集齐 **≥2 个互异
  #qNNN 且无已确认误杀** 才可 `[hard]`，否则 `[soft]`。上卷不得把一条
  soft 悄悄变 hard，除非合并后确实满足门槛。
- **泛化优先**：在"仍覆盖所有原有证据"的前提下取最一般的陈述；但**不得
  过度一般化**到把原来能抓的错放跑（上卷后要能推回每个原实例）。
- **命名**：合并后的 critic 仍守 `d-<域>-<错误家族>`，actor_skill 用
  `g-<域>-<能力>`；禁止 general/misc/common 这类泛词做家族段。
- R 判据仍是**一行**，全库 R 编号唯一；单文件 ≤400 行。
- 只改这两个技能库目录，不碰轨迹、Oracle、脚本、状态文件、报告、test。
- 拿不准某次合并会不会丢检测力 → **不合并**，原样留着，写进 `skipped`。

## 怎么做

1. 通读两个库，列出每条的 name/tags/正文要点、每条 R 判据的内容与 `依据:`。
2. 找**特例族**（多条指向同一原理）和**近重对**。
3. 对每个族/对，写出最一般表述，验证它能推回每个原实例（能，才合并；
   不能，拆开保留）。
4. 直接改文件：改写留下的那条、删掉被并入的、更新 `依据:` 并集、按门槛
   定 hard/soft。
5. 自查：编号唯一、frontmatter 可解析、无题面原句/答案值/条目 ID 泄漏
   （`依据:` 除外）、行数达标。

## 返回

只返回一个 JSON 代码块：

```json
{
  "merges": [
    {"kept": "g-xxx 或 R-...", "absorbed": ["...", "..."],
     "type": "abstract|dedup", "supporters_union": ["#q..","#q.."],
     "level_after": "hard|soft|n/a", "summary": "一句话"}
  ],
  "pruned": ["被删的技能名/R编号"],
  "skipped": ["拿不准没合的，一句话原因"],
  "actor_skills_before_after": [N, M],
  "critics_rules_before_after": [N, M],
  "needs_human": false
}
```

- **直接输出这个 JSON 块，前后不写别的**——长输出会撞 token 上限作废。
- 没有可合并的就返回空 `merges`/`pruned`（记 `noop`），不要为凑数硬合。
